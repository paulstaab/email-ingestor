# Repository instructions

## Design Documents
Refer to the current design documents before changing the implementation:

- `design/requirements.md`: Functional and nonfunctional requirements and the agreed feature scope.
- `design/architecture.md`: System boundaries, component interactions, processing flow, and reliability contract.
- `design/tech-stack.md`: Technology choices, compatibility constraints, and fixed operational defaults.
- `design/test-cases.md`: Planned test harness, test cases, and acceptance criteria linked to requirements.

- Keep the documents and implementation in sync.
- Extend the documents for new features requested by the user.
- Obtain user approval before updating existing points in the design documents. If an implementation change requires such an update, prepare the proposed documentation change for approval.
